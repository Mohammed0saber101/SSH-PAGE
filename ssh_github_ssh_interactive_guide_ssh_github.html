English Overview

What is SSH & Why Does Every Developer Use It?

SSH (Secure Shell) is a cryptographic network protocol that allows two computers to communicate, execute remote commands, transfer files, and push Git code securely over an untrusted network like the internet. It replaces insecure legacy protocols like Telnet and rsh by wrapping every byte in strong encryption and tamper-proof authentication.

ما هو بروتوكول SSH ولماذا يعتمد عليه كل مطور؟

بروتوكول القشرة الآمنة (SSH) هو بروتوكول شبكي تشفيري يتيح لجهازين الاتصال عن بُعد، وتنفيذ الأوامر، ونقل الملفات، ورفع الأكواد إلى GitHub بأمان تام عبر شبكات غير موثوقة مثل الإنترنت. صُمم ليحل محل البروتوكولات القديمة غير الآمنة مثل Telnet عبر تشفير جميع البيانات والتحقق الصارم من الهوية.

01. CONFIDENTIALITY | السرية

Symmetric encryption (ChaCha20 / AES-GCM) makes traffic unreadable to packet sniffers.

التشفير المتماثل يجعل البيانات غير قابلة للقراءة لأي متجسس على الشبكة.

02. INTEGRITY | سلامة البيانات

Cryptographic MAC (SHA-256 / Poly1305) detects if even 1 bit is modified in transit.

رموز التحقق (MAC) تكشف فوراً أي تلاعب بالبيانات أثناء النقل.

03. AUTHENTICATION | المصادقة

Host keys verify the server; asymmetric key pairs verify the user without sending passwords.

مفاتيح الخادم والمستخدم تثبت الهوية رياضياً دون إرسال كلمات مرور.

04. FORWARD SECRECY | السرية الأمامية

Ephemeral Diffie-Hellman keys ensure past sessions stay safe even if a key leaks later.

مفاتيح الجلسة المؤقتة تحمي الجلسات السابقة حتى لو تسرب المفتاح لاحقاً.

🔐 The 3 Cryptographic Pillars of SSH | الركائز الثلاث للتشفير في SSH

A common misconception is that SSH encrypts your entire session using your Public/Private key. In reality, SSH combines three different cryptographic primitives: من المفاهيم الخاطئة الشائعة أن SSH يشفر الجلسة بالكامل باستخدام المفتاح العام والخاص؛ والحقيقة أن المفتاح العام والخاص يُستخدمان فقط للمصادقة، بينما يجمع SSH بين 3 أنواع من التشفير:

1. Symmetric | التشفير المتماثل ⚡

Encrypts the Entire Session Traffic

Uses one shared session key (K) negotiated during Diffie-Hellman. Both client and server use this same key to encrypt and decrypt all terminal commands and files at ultra-high speed.

يستخدم مفتاحاً مشتركاً واحداً (مفتاح الجلسة K) لتشفير وفك تشفير جميع البيانات المتبادلة بسرعة فائقة طوال الجلسة، ويتم توليد مفتاح جديد لكل جلسة.

Ciphers: ChaCha20-Poly1305, AES-256-GCM, AES-128-CTR
2. Asymmetric | غير المتماثل 🗝️

Proves Identity (Authentication & KEX)

Uses a mathematical Key Pair: a Public Key (`.pub`) placed on GitHub/Server (like an open padlock) and a Private Key kept strictly on your machine to digitally sign login challenges.

يعتمد على زوج مفاتيح: مفتاح عام (`.pub`) يوضع في GitHub أو الخادم، ومفتاح خاص يبقى سرياً في جهازك فقط ويُستخدم لتوقيع تحدي الدخول لإثبات هويتك.

Algorithms: Ed25519 (Best), RSA-4096, ECDSA, Ed25519-SK
3. Hashing & MAC | التجزئة 🛡️

Fingerprints & Packet Tamper Proofing

One-way mathematical functions that create short fingerprints (SHA256:...) for host keys and append a MAC (Message Authentication Code) to every packet so tampering is impossible.

دوال رياضية ذات اتجاه واحد تُنتج بصمة المفتاح (SHA256) وتضيف رمز مصادقة الرسائل (MAC) لكل حزمة لضمان عدم تعديل أي بايت في الطريق.

Hashes: SHA-256, SHA-512, UMAC-128, Poly1305

FEATURE 01 • SFTP & SCP

Secure File Transfer | نقل الملفات الآمن

Copy files or directories over SSH with scp file.txt user@host:/path or interactive sftp user@host without setting up FTP servers.

نقل الملفات والمجلدات بأمان تام عبر نفس منفذ SSH باستخدام scp أو بروتوكول sftp التفاعلي.

FEATURE 02 • SSH-AGENT

Single Sign-On Key Memory | وكيل المفاتيح

ssh-agent holds your decrypted private key in RAM so you unlock your passphrase once and run git push or ssh seamlessly.

يحفظ ssh-agent مفتاحك الخاص في الذاكرة العشوائية مؤقتاً بحيث تدخل كلمة مرور المفتاح مرة واحدة فقط.

FEATURE 03 • MULTIPLEXING

ControlMaster Speedup | دمج الاتصالات

Reuses an existing TCP+SSH handshake for new terminals or Git operations, cutting connection time from ~800ms to ~20ms.

ميزة ControlMaster تعيد استخدام نفس النفق المفتوح لتسريع عمليات Git والاتصالات المتكررة بشكل هائل.

FEATURE 04 • REMOTE EXEC

Non-Interactive Automation | أتمتة الأوامر

Run single commands or pipe backups directly: ssh user@prod "docker ps" or stream compressed archives across servers.

تنفيذ أمر واحد عن بعد دون فتح جلسة كاملة مثل ssh user@server "uptime" وهو أساس عمل أداة Ansible.

FEATURE 05 • COMMIT SIGNING

Git Commit Verification | توقيع التعديلات

Since Git 2.34, your SSH key can cryptographically sign Git commits (replacing complex GPG keys) to get the green Verified badge on GitHub.

يتيح لك استخدام نفس مفتاح SSH لتوقيع الـ Commits في Git والحصول على شارة Verified الخضراء في GitHub.

FEATURE 06 • SSH CERTIFICATES

SSH Certificate Authority | شهادات SSH

Enterprises use an SSH CA (`ssh-keygen -s`) to issue short-lived signed certificates instead of manually copying `authorized_keys` to thousands of servers.

تستخدم الشركات الكبيرة سلطة شهادات (SSH CA) لإصدار مفاتيح مؤقتة تنتهي صلاحيتها تلقائياً بدلاً من إدارة المفاتيح يدوياً.
